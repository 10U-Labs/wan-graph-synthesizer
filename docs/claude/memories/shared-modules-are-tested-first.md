# The shared modules are tested before the tests that stand on them

When a shared test helper is wrong, the run that fails should name the helper. The nine modules under `lib/python/` — `repo_utils`, `test_fixtures`, `test_handler_contracts`, `test_http_doubles`, `test_module_utils`, `test_published_syntheses`, `test_s3_store_mock`, `test_terraform_config` and `test_terraform_drift` — are the fixtures, doubles, loaders and readers most of the suite is written on top of, and until GitHub issue #53 every workflow ran them in the same `pytest` command as the tests that import them. A defect in one reached the reader as a failure in whatever tier consumed it, named for the subject that tier was testing: a probe that reads a present log group as absent failed a post-deployment tier and named the log group, and no result anywhere named the module that was wrong. `docs/tenets/tests/OVERVIEW.md`, under "Nothing Is Trusted Before What It Presumes", is the rule that settles it — the result presuming least is the one that names the defect.

Each workflow that runs Python tests carries a job named `test-repo-libraries`. It starts when the workflow does and runs before every job in that workflow whose tests import the modules, and the edge is written on each of those jobs rather than left to arrive down the chain: in `api_endpoint_tenants_wan_post.yml` the `needs:` of `unit-tests`, `pre-deployment-integration-tests` and `post-deployment-integration-tests` all name it. An edge that is only transitive disappears the moment somebody redraws the graph, which is what GitHub issue #56 then did. The two workflows without the job are `documentation.yml` and `www_spa.yml`, which run no Python tests.

Every workflow runs every module's tests, not the subset its own tests import. Scoping the job to the import graph makes its contents something nobody maintains, so a new import silently widens what a workflow should have been checking and nothing reports that it did not. The modules are pure Python exercised against literals, so the whole of `test/lib/python/` is cheap to run. The same reasoning moved the coverage gates: every one of those jobs carries the same nine `--cov=lib/python/<module>` flags at `--cov-fail-under=100`, so a module that loses coverage fails in every run, and the per-workflow lists GitHub issue #52 wrote are gone. What stays gated in a `unit-tests` job is that workflow's own source, such as `--cov=src/api/endpoints/tenants/wan/post/lambdas/synthesizer`. `api_common_routing.yml` and `api_common_storage.yml` gate nothing at all now, their stacks being OpenTofu with no Python in them.

The job carries one step per kind of test that exists under `test/lib/python/`, and no step for a kind that does not. Today that is a unit step over the nine `pre_deployment/unit/` directories and an integration step over the four `pre_deployment/integration/` directories, unit first because it presumes less. `test_http_doubles` is gated on the integration step and hands it `test/lib/python/test_http_doubles/pre_deployment/`, both tiers in one directory argument: the module publishes a stub API server, the code that answers a request only runs when a client sends one, and coverage is counted per `pytest` invocation, so a gate seeing only the unit files would report the server untested as covered. There is no `post_deployment/` directory anywhere under `test/lib/`, so there is no step for one. Do not write a placeholder step for a directory that is not there.

Two shapes look right and cannot work, which is why both are written out in a comment beside the job. A workflow of its own for these modules, named for the directory the way `seed.yml` is named for `scripts/seed.py`, would run beside the workflows that consume them: GitHub Actions gives no ordering between workflows triggered by the same push, and this repository declares none — `grep -rn "workflow_run\|workflow_call" .github/workflows/*.yml` returns nothing. It would report on the modules at the same time as, or after, the tests that already stood on them, which is how a suite ends up green with a red library on the same push. An expression `if` reading the job's result is not a substitute for the `needs:` edge either, because a job that only reads another job's result can start before that job has finished.

In `seed.yml` the job is first and gated on nothing, carrying no `needs:` and no `if:`, beside the nine static-analysis checks and `yamllint`, which are gated on nothing too. Everything that tests or seeds is behind it: `unit-tests` and `integration-tests` name it in a `needs:` of their own and carry no `if` at all, `seeding` names it in the flat `and` beside the nine checks and those two tiers, and `e2e-tests` names it beside `seeding`. A red one skips `unit-tests` and `integration-tests` under the default `needs:` semantics and leaves `seeding` no `success` to read, so nothing is PUT to the live API behind a broken shared module. See [seed-tests-every-push](seed-tests-every-push.md).

Each of them lists `test/lib/python/**` in its `paths`, one entry replacing the per-module list. A workflow that runs a test file has to be startable by a change to it, and the job runs all nine subtrees whatever that workflow imports. See [where-a-test-runs-follows-what-starts-it](where-a-test-runs-follows-what-starts-it.md).

GitHub issue #56 landed after this and removed most of the `needs:` edges in these workflows so the jobs run concurrently — see [every-check-is-its-own-job](every-check-is-its-own-job.md). It dropped this job's own edge to `static-analysis`, which no longer exists as a job, and kept the edges out of it. The tenet does not supply the reason for keeping them — it fixes what a result means, not what may be attempted — so two reasons it does not cover are written in the comment beside the job: a run that carries on past a broken module spends a `tofu apply`, a seeding pass and up to the 900 seconds of `_BUILD_DEADLINE_SECONDS` in `test/scripts/seed/post_deployment/e2e/conftest.py` on results that will be thrown away, and a reader facing a screenful of red consumer jobs has to be told which one to read, where one red job and the rest skipped has already told them.
